# AI 多模态学习助手项目需求文档

## 1. 项目背景

随着大语言模型、RAG 检索增强生成、目标检测和智能体技术的发展，AI 已经能够在学习资料管理、知识问答、图像理解和内容生成等场景中发挥重要作用。对于学生而言，课程资料通常包括 PDF、PPT、实验代码、作业要求和课堂笔记等多种形式，信息分散、检索效率较低，复习和整理成本较高。

本项目拟设计并实现一个面向课程学习场景的 AI 多模态学习助手。系统支持课程资料上传、知识库问答、图片目标检测、学习内容总结和报告大纲生成等功能，通过 Agent 判断用户意图并调用对应工具完成任务。项目综合应用课程中涉及的深度学习基础、YOLO 目标检测、大模型、RAG 知识库和 Dify/Agent 工作流等内容，既能体现课程知识点，也具备较好的演示效果和扩展价值。

考虑到课程大作业周期较短，本项目第一阶段优先采用 Streamlit 快速实现可演示系统，保证核心 AI 功能完整跑通。后续可升级为 Vue + FastAPI 架构，提升系统界面效果、接口规范性和工程化水平。

**系统采用可插拔 LLM Provider 架构（Pluggable LLM Provider），统一封装模型调用接口，支持云端兼容 API 和本地部署模型无缝切换，为后续扩展其他大语言模型提供统一接口。**

## 2. 用户需求

本系统的主要用户是课程学习者、项目小组成员和需要整理课程资料的学生。用户希望通过一个统一入口完成课程资料检索、智能问答、图像检测和学习内容生成。

具体需求如下：

1. 用户可以上传 PDF、TXT、Markdown、PPT 等课程资料。
2. 系统可以解析上传文件，并构建课程知识库。
3. 用户可以围绕课程内容进行提问，系统基于知识库返回答案。
4. 系统回答应尽量给出资料来源，方便用户追溯原文。
5. 用户可以进行普通大模型聊天，获取课程相关解释和学习建议。
6. 用户可以上传图片，系统调用 YOLO 模型完成目标检测。
7. 系统可以将 YOLO 检测结果整理为自然语言分析说明。
8. 系统可以根据课程资料生成学习总结、复习提纲、报告大纲或 PPT 提纲。
9. 系统可以保存基础对话历史和上传记录，便于后续查看。
10. 系统界面应简单直观，适合课程演示和答辩展示。

## 3. 功能模块

| 模块名称 | 功能说明 | 优先级 |
|---|---|---|
| 前端交互模块 | 提供聊天界面、文件上传、图片上传、结果展示和侧边栏功能入口 | 必做 |
| 文件解析模块 | 解析 PDF、TXT、Markdown、PPT 等学习资料，提取可检索文本 | 必做 |
| RAG 知识库模块 | 对课程资料进行文本切分、Embedding 向量化、向量存储和相似度检索 | 必做 |
| LLM 问答模块 | 接入云端兼容 API、本地模型或其他大语言模型，生成自然语言回答 | 必做 |
| 学习辅助生成模块 | 生成课程总结、复习提纲、报告大纲、PPT 提纲等内容 | 必做 |
| YOLO 检测模块 | 对用户上传图片进行目标检测，输出类别、置信度和检测框 | 加分 |
| 检测结果解释模块 | 将 YOLO 检测结果输入大模型，生成自然语言分析说明 | 加分 |
| Agent 调度模块 | 根据用户输入判断任务类型，自动调用 RAG、LLM、YOLO 等工具 | 加分 |
| 对话历史模块 | 保存用户问题、系统回答、时间和任务类型 | 必做 |
| 联网搜索模块 | 对知识库无法覆盖的问题进行联网搜索补充 | 选做 |
| 工作流可视化模块 | 展示 Agent 的任务判断和工具调用过程 | 争优 |
| Vue 升级接口预留 | 将核心 AI 能力封装为服务函数，方便后期改造为 Vue + FastAPI | 选做 |

## 4. 技术架构

### 4.1 第一阶段推荐架构

课程大作业第一阶段采用 Streamlit + Python 模块化架构。该方案开发速度快、部署简单、适合 AI Demo 演示，能够让小组将主要精力放在 RAG、YOLO、大模型和 Agent 功能上。

推荐技术选型如下：

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 前端交互层 | Streamlit | 快速构建聊天、上传、图片展示等页面 |
| 应用逻辑层 | Python 模块化代码 | 将 RAG、LLM、YOLO、Agent 封装为独立服务 |
| Agent 层 | LangChain / 简化规则路由 / Dify 工作流 | 判断用户意图并选择调用工具 |
| RAG 层 | LangChain + Chroma / FAISS | 实现文本切分、向量化、检索和问答 |
| Embedding 模型 | bge-small-zh / text2vec / 通用 Embedding 模型 | 将文本转换为向量 |
| 大模型 | 云端兼容 API / 本地模型 / fallback 模式 | 负责回答生成、总结生成和结果解释 |
| 目标检测模型 | YOLOv8 / YOLOv5 | 对上传图片进行目标检测 |
| 数据存储 | SQLite + 本地文件夹 + 向量数据库 | 保存对话历史、上传资料和向量数据 |
| 运行方式 | 本地运行 | 适合课程演示和答辩 |

### 4.3 后续升级方向

在课程版本完成后，可以将系统升级为 Vue + FastAPI 架构。升级时前端由 Vue 负责，后端由 FastAPI 提供接口，RAG、YOLO、LLM 等核心模块可以继续复用。

升级后的架构如下：

```text
Vue 前端
  ↓ HTTP 请求
FastAPI 后端
  ↓
AI 服务模块
  ├── RAG 知识库
  ├── LLM 问答
  ├── YOLO 检测
  └── Agent 调度
```

因此，在第一阶段开发时应注意模块化设计，避免将所有逻辑都写在 `app.py` 中。Streamlit 只负责页面展示和用户交互，核心 AI 能力应封装为独立函数或类，便于后续迁移。
