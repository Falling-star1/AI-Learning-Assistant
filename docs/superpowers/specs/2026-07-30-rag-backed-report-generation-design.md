# 基于 RAG 的报告生成设计

## 1. 目标

让“学习辅助生成”模式复用已经建立的课程知识库。学习报告和实验报告应优先依据检索到的课程片段生成，并在页面和下载内容中展示引用来源。

本次只补齐报告与现有 RAG 的功能链路，不更换当前关键词检索实现，也不新增自动保存报告的行为。

## 2. 设计选择

采用 Agent 路由层编排方案：

1. Agent 根据报告主题调用 RAG 检索。
2. RAG 返回结构化的相关片段。
3. Agent 将片段内容传给报告生成器，并整理引用来源。
4. 报告生成器根据 LLM Provider 和上下文生成报告。
5. Streamlit 展示报告、知识库使用状态和引用来源，并提供 Markdown 下载。

这样可以保持模块职责清晰：

- RAG 模块只负责检索。
- 报告模块只负责组织提示词和生成报告。
- Agent 模块负责串联业务流程。
- Streamlit 只负责输入和结果展示。

## 3. 数据流

```text
用户输入报告主题
  -> Agent 检索知识库
  -> 获取相关 SearchResult
  -> 转换为上下文片段和引用信息
  -> 报告生成器调用 Qwen 或 fallback
  -> 返回报告正文、Provider、引用来源和下载文件名
  -> Streamlit 展示并提供下载
```

## 4. 接口调整

### RAG

新增一个公开检索函数，接收查询、知识库路径和 `top_k`，返回 `SearchResult` 列表。课程问答与报告生成共用该函数，避免重复组织检索逻辑。

### 报告生成器

`generate_report` 新增可选的 `context_chunks` 参数。调用云端 Provider 时，课程资料作为上下文传入；调用 fallback 时，本地模板直接整理检索片段。

`ReportResult` 增加知识库使用状态，但不保存本地文件。下载文件名仍由报告模块生成。

### Agent

“学习辅助生成”分支先检索，再调用 `generate_report`。返回结果增加：

- `knowledge_status`：`ready` 或 `empty`
- `sources`：资料名、片段编号和相关度

### Streamlit

报告回复下方展示简洁的参考资料列表。无相关资料时显示提示，但仍允许生成通用草稿。下载的 Markdown 正文中也包含参考资料章节。

## 5. 生成规则

### 有相关资料

- 学习报告必须包含资料要点、练习题和参考答案。
- 实验报告优先遵循用户输入的格式要求。
- Qwen Provider 应明确收到课程资料上下文，并被要求避免编造资料中没有的课程事实。
- fallback Provider 应将检索片段整理进报告，保证没有 API Key 时也能完整演示。
- 报告末尾追加“参考资料”章节，引用格式为“资料名，片段 N”。

### 无相关资料

- 不阻断报告生成。
- 返回通用报告草稿。
- 页面明确提示“本次报告未使用知识库资料”。
- 不生成虚假的引用来源。

## 6. 错误处理

- 知识库文件不存在或没有相关结果时，按无资料流程处理。
- 报告生成失败时，由现有页面异常处理机制显示错误，不创建残留报告文件。
- 用户未提供实验报告格式时，继续使用默认实验报告结构。

## 7. 测试范围

使用测试驱动方式补充以下行为：

1. RAG 公共检索函数返回结构化结果。
2. 云端 Provider 能收到检索上下文。
3. fallback 报告包含检索片段和参考资料。
4. Agent 报告分支返回知识库状态和来源列表。
5. 空知识库仍能生成通用报告且来源为空。
6. 报告仅生成可下载内容，不自动写入文件。

## 8. 验收标准

- 上传课程资料并建库后，生成的报告能引用相关资料片段。
- 页面可看到本次报告是否使用知识库及具体来源。
- 下载的 Markdown 包含相同报告内容和参考资料。
- 没有 API Key 和没有知识库时均能给出明确、可演示的结果。
- 现有 RAG 问答、YOLO、历史记录和报告下载测试保持通过。
